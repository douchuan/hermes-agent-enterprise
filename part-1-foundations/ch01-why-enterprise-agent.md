# 第 1 章：为什么企业需要独立部署 AI Agent

员工每天的工作，通常由以下几类活动构成：

- 在多个系统之间切换，查找资料、确认状态、同步信息。
- 处理重复性任务：写周报、整理会议纪要、更新工单、生成报告。
- 解决复杂问题：排查线上故障、分析数据异常、评估方案可行性。
- 与客户、同事和跨团队沟通，确认需求、协调进度。

这些活动中，有相当一部分并不需要员工重新发明轮子，但需要他们投入时间、精力和注意力。传统软件通常要求员工自己操作和组织这些工作——打开不同的页面、复制粘贴信息、在不同的权限和上下文之间切换。

当 AI Agent 出现后，员工多了一种选择：**让一个持续的助手参与到这些工作中，协助完成信息查找、任务执行和上下文积累。**

本章要回答的问题是：这种变化对企业意味着什么，以及为什么企业需要认真考虑为员工提供自己的 Agent。

## 从 AI 助手到工作伙伴

市面上已经有很多基于大语言模型的聊天工具。它们可以回答问题、翻译文本、生成代码和撰写文档。这类工具通常的工作方式是：用户输入问题，模型返回一次回答，对话结束后上下文随之消散。

Hermes Agent 的运行方式有所不同。它由 [Nous Research](https://github.com/NousResearch/hermes-agent) 开源，设计为一个可以**长期运行**的 Agent，而不是单次问答界面。它的核心特征包括：

- **持续记忆（Memory）**：Hermes 会将工作中积累的上下文——用户偏好、项目信息、环境配置、历史经验——保存在持久化的记忆中，并在后续会话中主动调用。这意味着 Agent 不需要每次重新了解员工的工作背景。
- **技能系统（Skills）**：Hermes 可以在使用过程中，将反复执行的工作方法转化为可复用的 Skill。这些 Skill 以结构化的形式保存在本地，支持后续调用和改进。官方文档将其描述为一个"学习循环"（learning loop），Agent 会从经验中创建并持续优化这些技能[^skills]。
- **工具调用能力**：Hermes 可以通过 MCP Server 等方式连接外部工具和系统，执行代码、查询 API、操作文件等。它不是仅停留在文本生成层面，而是能够实际完成工作步骤。
- **长期在线运行**：Hermes 设计为在服务器上持续运行，支持 Bot Mode 和定时自动化任务，而不是仅在被打开时才响应。

[^skills]: 参见 Hermes Agent 官方文档关于 [Skills 的介绍](https://github.com/NousResearch/hermes-agent/blob/main/website/docs/user-guide/features/skills.md)。Skills 的创建和改进机制仍在持续演进中，本书后续章节会结合实际部署情况进一步讨论。

这些特征的组合，使得 Hermes Agent 更接近一个**持续参与工作的助手**，而不是仅在需要时才被召唤的工具。

员工可以在日常工作中持续与 Agent 互动。随着使用时间的增长，Agent 积累的记忆和技能会逐渐提升它在特定工作环境中的辅助能力。对于需要反复处理相似任务的员工而言，这意味着更少的上下文重建、更快的响应速度和更高的工作质量。

但我们需要坦诚地说一件事：

**Hermes 的记忆和技能机制是个人级别的实现，并非企业级知识管理系统。** 它的记忆以本地文件形式持久化（具体存储格式和目录结构取决于部署配置），Skill 同样以文件形式保存在 Agent 的运行环境中。它们没有内置的跨用户共享机制、权限控制系统或企业级审核流程。这意味着，单个员工的记忆不等于团队共享知识库，个人 Skill 也不等同于组织验证过的标准流程。

正是这种"个人级"的特征，引出了本章最重要的论点。

## 让工作经验得以积累

企业面临一个长期存在但鲜有技术解决方案的问题：**当员工离开或转岗时，工作经验很可能随之流失。**

这里说的"经验"，不一定是正式文档或标准操作流程。更多时候，它们是员工在日常工作中逐渐积累的隐性知识：

- 某个系统的配置窍门和已知陷阱。
- 处理特定类型工单的经验和判断依据。
- 排查线上问题的路径和常用命令。
- 与客户沟通中形成的有效表达方式。
- 项目决策时的权衡考虑和背景信息。

这些知识通常分散在员工的日常工作记录、邮件往来、聊天消息和反复尝试形成的工作方法中。它们可能存在于个人笔记里，可能只留在记忆中，也可能根本没有被显式地记录下来。

当员工离职或转岗后，即使岗位职责和文档体系仍然存在，接替者也可能需要重新探索那些已经被前人解决的问题。

### Hermes 的记忆与 Skill 提供了什么可能

如果员工在日常工作中持续使用 Agent，那么有价值的经验就有机会逐渐沉淀为可查询的记忆，将部分工作方法固化为可复用的 Skill。

这不是说 Hermes 会自动、完整、准确地保存员工的全部工作经验。实际情况更加微妙：

- **记忆是选择性的**：Hermes 会在对话和任务执行过程中，提取它认为重要的信息存入记忆。提取的质量取决于模型的判断和配置方式。
- **Skill 是过程性的**：Skill 记录的是工作方法，而不一定是方法背后的完整上下文和判断逻辑。
- **它们是个人维度的**：每个 Agent 的记忆和 Skill 属于特定的员工，不是自动在组织内共享的公共资源。

但即使如此，这种能力仍然为工作经验的积累提供了一个新的基础——**员工在日常工作中产生和使用 Agent 的同时，经验就有机会被结构化地留存下来。**

这里的关键区分是：

> **员工的个人记忆不等于企业共享知识库，但个人工作经验可以经过筛选、验证、授权和治理，逐步转化为企业能够持续利用的知识资产。**

本书后续章节将讨论，如何通过企业级架构和治理机制，在保护隐私和权限边界的前提下，实现这种从个人经验到组织资产的转化路径。

## 从个人效率到企业能力

当一个员工使用 Agent 提升个人效率时，影响主要局限于个人层面。

当越来越多员工能够借助 Agent 工作时，企业可能获得的新能力就不再只是"每个人更快了"：

- **知识积累的日常化**：员工在使用 Agent 的过程中，经验被持续沉淀。知识管理不再是一项额外的、需要专门投入的活动，而是工作流程的副产品。
- **经验复用的可能性**：经过验证和治理的工作方法可以转化为可在组织内共享的 Skill，减少重复探索。
- **工作流的重新设计**：当 Agent 能够可靠地承担部分任务时，部分工作流程可以被重新设计——减少不必要的人工环节，让员工更多聚焦于判断、决策和创造。
- **组织连续性的增强**：当员工离职或转岗时，Agent 保留的记忆和技能可以帮助接替者更快地进入工作状态，降低人员变动带来的知识断层。

这些能力不是自动产生的。它们取决于企业如何组织 Agent 的使用、如何管理 Agent 的权限和访问、如何处理 Agent 积累的数据，以及如何建立知识共享和复用的机制。

如果一个企业能够有效组织这些能力，它就可能在知识积累、经验复用和组织协作方面，逐渐形成与传统工作方式不同的优势。

AI 可能改变企业之间竞争的方式，不是因为某个企业"用了 AI"，而是因为它把 AI 融入了日常工作，并建立了持续改进的机制。

## 企业需要把 AI 用好

企业不能只把 AI 当作可有可无的新工具，而应认真思考如何将 AI 融入工作，并把它真正用好。

"用好 AI"不是指选一个最强大的模型或部署最多的 Agent。它意味着：

- 让 Agent 真正参与到员工的日常工作中，而不是停留在偶尔试用的阶段。
- 让 Agent 能够访问它需要访问的企业系统和数据，而不是把它限制在完全隔离的沙箱中。
- 建立统一的服务和治理体系，让每个员工的 Agent 都能长期、稳定、安全地运行。
- 将个人维度的能力，逐步转化为组织层面的能力。

这些要求引出了一个核心矛盾：

**为了让 Agent 产生真正的业务价值，它必须能够访问真实的企业系统和数据；而一旦它开始访问这些系统和数据，安全、权限和治理就不再是可选项，而是必要条件。**

## 安全是业务持续运行的基础

当 Agent 开始处理真实业务任务、访问敏感信息、调用企业工具时，企业必须认真考虑以下问题：

- Agent 能访问哪些业务系统和数据？
- Agent 能代表员工执行哪些操作？
- 如何防止权限超出业务需要？
- 如何在员工离职或转岗时调整权限，并保留适当的工作经验？
- 如何避免个人记忆中的敏感信息被不恰当地共享？
- 当 Agent 出现错误或执行了不符合预期的操作时，企业如何发现和处理？

这些问题不是为了阻止企业使用 AI。它们的目的恰恰相反——**让企业能够更放心地使用 AI，并让 AI 的业务价值能够长期持续。**

本书接下来将围绕这些问题，逐步构建一个企业级的 Hermes Agent 部署架构。我们将从理解 Hermes Agent 的运行机制和安全边界开始（第 2 章），然后逐步构建身份认证、运行环境隔离、网络访问控制、工具治理、凭证管理、审批机制、可观测性和平台实现。

安全的宗旨是服务业务。既然企业需要认真采用 AI，就必须同时考虑如何安全、可靠地使用 AI。

## 本书将如何展开

本书以 Hermes Agent 为主要运行时参考，以企业部署和安全治理为主线。各部分的大致分工如下：

- **第一部分**（第 1–2 章）：建立问题认知，理解 Hermes Agent 的运行机制和安全边界。

- **第三部分**（第 7–9 章）：实现企业工具访问与安全治理——Tool Gateway、凭证管理和审批机制。
- **第四部分**（第 10–12 章）：建立安全运营能力——可观测性、Prompt Injection 防护和平台生命周期管理。

每一部分都配套有可在本地运行的实验示例（位于 `examples/` 目录），帮助读者验证关键机制。
