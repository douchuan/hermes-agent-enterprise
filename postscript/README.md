# 后记：从 AI Agent 到数字员工

写这本书的过程中，我逐渐意识到，自己真正感兴趣的，可能不只是如何在企业中部署一个 AI Agent，而是一个更大的问题：**未来的企业，会如何使用和管理数字员工？**

今天，我们已经可以让 AI Agent 调用工具、访问外部系统、执行多步骤任务，并通过记忆和技能机制积累上下文与工作方法。随着这些能力不断成熟，AI Agent 不再只是一个回答问题的聊天窗口，而开始具备参与日常工作的可能。

我更愿意把这种形态理解为数字员工。

## 数字员工也需要经历一个完整的工作周期

一个真实的员工进入企业，并不是办理完入职手续就可以立即独立工作。

企业需要筛选合适的人选，完成招聘，让新员工熟悉业务、接受培训，再经过一段时间的试用，逐步承担正式的工作职责。在工作过程中，企业还需要管理其权限、评估工作表现，并在员工离职时做好交接。

如果把 AI Agent 看作数字员工，这套逻辑同样值得借鉴。

数字员工也需要经过筛选、引入、培训、试用和正式上岗。企业需要判断它适合承担什么工作，为它配置必要的工具和权限，让它熟悉业务规则，再通过真实任务验证它的表现。只有当它的能力、可靠性和权限边界符合要求时，才能逐步扩大它的职责范围。

当数字员工不再适合某项工作，或者企业需要更换底层模型、调整业务流程时，也需要有明确的变更和交接机制。

当然，数字员工与真实员工并不相同。AI Agent 不具备人的全部判断能力，也不能简单套用传统的人力资源管理方式。但从企业运营的角度看，二者有一个重要的共同点：**都不能只看引入成本，还需要考虑如何让它们真正胜任工作，以及如何在整个工作周期中持续管理它们。**

## 培训数字员工，首先要理解企业的业务

我认为，数字员工能否真正创造价值，关键并不只是模型有多强，也不只是 Agent 能够调用多少工具。

更重要的是，它是否理解自己所处的业务环境。

同样一个 AI Agent，放在不同企业、不同部门，承担的工作可能完全不同。财务部门关注账目准确性和审批规则，销售部门关注客户信息和跟进流程，研发部门则可能更关心代码、测试与发布流程。

即使使用相同的模型和 Agent 框架，也不能期待它们在这些场景中开箱即用。

企业需要有人梳理工作流程，明确任务边界，连接必要的业务系统，把隐含的工作经验转化为可执行的规则，并通过真实任务反复验证效果。这实际上是一种业务适配和持续培训的过程。

这也是我关注 Hermes Agent 的原因之一。它的 Memory 和 Skills 机制，为 Agent 保留上下文、复用工作方法提供了基础。但这些机制本身并不能自动让 Agent 理解一家企业，更不能保证它掌握的经验始终正确。企业仍然需要参与知识整理、结果验证和权限管理。

因此，未来数字员工服务的价值，可能不只是提供一个可以运行的 Agent，而是帮助企业把 Agent 培养成能够承担特定工作的数字员工。

## 未来的服务商，可能需要走进企业现场

这让我想到 FDE，也就是 Forward Deployed Engineer，通常可以理解为前线部署工程师。

这类角色的特点，是深入客户的实际业务环境，不仅交付技术产品，还需要理解客户的问题，将产品能力与真实工作流程结合起来。

我认为，数字员工的部署和交付也可能沿着类似的方向发展。

企业当然可以自行安装和运行 AI Agent，但让一个 Agent 真正进入业务流程，往往远不止部署软件那么简单。服务商可能需要与业务人员一起梳理任务，理解现有系统和数据，确定数字员工的职责范围，设计工具访问和权限控制，再通过试运行逐步调整。

换句话说，部署数字员工的人，也需要懂企业的业务。

未来可能会出现专门提供数字员工服务的团队。他们既理解 AI Agent 的运行机制，也熟悉企业系统集成、安全治理和业务流程。他们帮助企业选择合适的数字员工，为其配置工作环境，完成培训和试用，并在正式上岗后持续观察效果、处理问题、改进能力。

这种服务既不是单纯的软件销售，也不是传统意义上的系统集成。它更接近一种持续的交付与运营服务：让数字员工真正进入工作，而不是停留在演示环境中。

## 从软件平台到数字员工服务

回过头来看，这本书讨论的独立部署、运行环境、身份认证、权限控制、工具网关、记忆治理和审计机制，都是企业使用数字员工时可能需要的基础能力。

这些技术解决的是数字员工如何安全、可靠地运行。但如果把视角放到更长远的未来，还会出现更多问题：

- 企业如何判断一项工作适不适合交给数字员工？
- 如何选择合适的模型、Agent 和工具？
- 如何让数字员工熟悉企业的业务规则？
- 如何通过试用和评估，判断它是否具备正式上岗的条件？
- 如何在业务变化、模型升级或人员交接时，持续维护它的能力？
- 如何衡量数字员工带来的实际价值，而不仅仅是调用了多少次模型、消耗了多少 Token？

这些问题已经超出了单个 Agent 的运行范畴，涉及数字员工的整个生命周期。

从这个角度看，我最初想要构建的 SaaS AI Agent 服务，也许可以理解为一个更完整的数字员工平台：为企业提供数字员工的运行环境、管理能力和业务集成，并进一步支持它们从引入、培训、试用到正式上岗的全过程。

平台负责提供可复用的基础能力，而深入业务的交付与服务，帮助企业把这些能力转化为实际成果。随着实践积累，一些经过验证的工作流程、技能和配置，也有机会在适当的授权与隔离机制下沉淀下来，成为可以复用的服务能力。

这当然还需要持续探索和验证。但它给了我一个比单纯部署 Agent 更清晰的方向。

## 写在最后

AI Agent 的发展，让我们有机会重新思考软件与工作的关系。

过去，企业购买软件，再安排员工学习和使用软件。未来，企业可能不仅会购买软件，也会引入能够直接参与某些工作的数字员工。当然，这并不意味着数字员工可以完全取代真实员工。更现实的方向，是人和 AI 各自承担适合自己的工作，并通过明确的职责与协作机制完成任务。

如果这个方向成立，那么未来企业之间的差异，可能不仅在于使用了什么模型、部署了多少 Agent，还在于能否持续培养、管理和改进数字员工，让它们真正融入业务。

这也是我写这本书的初衷之一：从 Hermes Agent 出发，理解构建企业级 Agent 平台所需要的技术与治理机制，并进一步探索这些能力如何服务于真实的企业工作。

这条路还很长。希望这本书能成为一个起点。
